# 跨agent接入

## 安装

将整个pdd-main-image-edit文件夹复制到目标agent实际使用的skills目录，保留所有相对文件。不要只拷SKILL.md。
本机发现的WorkBuddy用户技能目录为~/.workbuddy/skills/；其他版本、电脑以本地实际目录为准。刷新技能后，用“使用pdd主图修改”触发；Codex也可用$pdd-main-image-edit。

不绑定Codex私有工具、模型ID或付费API。不包含密钥、令牌、用户配置或账户数据。不依赖其他技能。

## 执行协议

1. 新任务先确认A/B模式，取得原图与新产品实拍。
2. 实际看图，建立映射、原文、目标文案与锚点。
3. 核实图片工具支持编辑、几张参考、中文表现；能力弱就用短模板。
4. 本地路径不能直接给图片工具时，用其已有附件上传方式，记录资源标识；不可访问路径不算已上传。
5. 先生成一张完整样图，QA后用户确认，再逐张扩展。
6. 异步工具必须等真正完成，下载并验证能打开及实际尺寸；任务ID不等于完成。
7. 逐张QA，报告失败与未完成数量。

不用固定的image_gen、generatedImage、view_image或特定MCP名字。环境没有OCR就人工读字，没有审阅子代理由主agent检查，不硬依赖另一款模型。

## 辅助脚本

Python 3可运行build_batch.py，无需网络或密钥。review_batch.py需Pillow；没有时用现有查看器做同等检查，不强制装一套大环境。两脚本都不调用图片模型、不编辑单张最终主图。

输入参考包、输出总览只作辅助。只能文生图的工具无法保证产品一致；中文无法正确生成时，不能靠本地叠字偷偷补完。

仅能上传一张参考图时，可运行prepare_reference.py生成双区域参考包，不需要目标agent临时写拼图程序。调用时须明确“1号产品／2号版式”，最终输出仍为一张完整广告。

## 已验证与未验证

本项目已经用内置图片工具验证“原始整组实拍+原主图版式+模型完整直出”，用户确认并完成14张。本包的安装和脚本可单独验证，但不等于WorkBuddy实机生图或较弱图片模型已验证。目标环境真实试跑后，再记录实际工具、模型、样图与结果。
